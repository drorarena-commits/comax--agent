# מפרט: מאזין התור (`listen`)

> **מה זה:** תהליך אחד שרץ תמיד במחשב המשרד, קורא משימות מ-`queue/inbox/`,
> מריץ אותן דרך `tools/run.js`, וכותב תוצאות ל-`queue/done/`.
>
> **למה:** כדי שדרור יוכל לבקש משימות מהנייד דרך שיחת Cowork. Claude בשיחה
> כותב קובץ לתור; המאזין הוא מה שגורם לו לרוץ. בלעדיו הקובץ פשוט מחכה.
>
> **מי בונה:** Claude Code. המפרט הזה נכתב על ידי Claude ב-Cowork, שקרא את
> `run.js`, את `config/comax.config.json` ואת 16 קבצי הסוכנים, אבל **לא יכול
> להריץ כלום** — אז כל הנחה כאן טעונה אימות מול הקוד בפועל.

## 0. מה כבר קיים ואסור לשכפל

| קיים | איפה | המאזין משתמש בו, לא מחליף |
|---|---|---|
| דיספצ'ר משימות | `tools/run.js` | קורא לו כתהליך בן |
| מנעול מושב יחיד | `src/lock.js` — `acquire`, `busyMessage` | מכבד אותו |

## 2. קובץ משימה — `queue/inbox/<id>.json`

`id` = `YYYYMMDD-HHMM-<slug>`, לדוגמה `20260915-1620-stock`.

```json
{
  "id": "20260915-1620-stock",
  "created": "2026-09-15T16:20:00+03:00",
  "source": "cowork",
  "request": "כמה נשאר מ-004900 בראשי",
  "mode": "task",
  "task": "stock-export",
  "input": { "code": "004900" },
  "context": "",
  "notify": true
}
```

| שדה | חובה | הסבר |
|---|---|---|
| `id` | ✅ | ייחודי. שם הקובץ זהה לו |
| `request` | ✅ | מה דרור ביקש, במילים שלו. לתיעוד ולהודעת הטלגרם |
| `mode` | ✅ | `task` או `agent` |
| `task` | mode=task | שם משימה קיימת מ-`src/tasks/` |
| `input` | mode=task | ה-JSON שמועבר ל-`--json` |
| `agent` | mode=agent | שם סוכן מ-`.claude/agents/` |
| `prompt` | mode=agent | **עומד בפני עצמו.** ראה §6 |
| `context` | ❌ | רקע חופשי לבן אדם שיקרא את הלוג |
| `notify` | ❌ | ברירת מחדל `true` |

### שני המצבים

**`mode: "task"`** — פעולה דטרמיניסטית. המאזין מריץ:

```
node tools/run.js <task> --json '<input>'
```

אין מודל, אין טוקנים, אין הקשר. זה הרוב.

**`mode: "agent"`** — צריך שיפוט. המאזין מריץ סשן Claude Code קצר:

```
claude -p "<prompt>" --agent <agent>
```

סשן חדש בכל משימה, נסגר בסוף. **לא סשן ארוך מתמשך** — הצטברות הקשר היא בדיוק
מה שהארכיטקטורה הזאת נמנעת ממנו.

## 3. ירוק ואדום — נקבע מהקוד, לא מרשימה

`run.js` כבר יודע את זה. ב-`--list` הוא קורא לכל משימה את `meta.writes`:

```js
writes: m.writes !== false
```

**ברירת המחדל היא `true`.** משימה בלי `meta` מפורש נחשבת כותבת. זו התנהגות
נכונה ויש לשמר אותה — המאזין לא מנחש.

| | `meta.writes === false` | `meta.writes !== false` |
|---|---|---|
| **דוגמאות** | `customer-history`, `stock-export`, `quote-read` | `quote-new`, `document`, `items-import`, `transfer-to-invoice` |
| **המאזין** | מריץ עד הסוף לבד | מריץ **בלי** `--confirm`, ואז עוצר |
| **`--confirm`** | לא רלוונטי | רק אחרי אישור מ-§5 |

⛔ **המאזין לא מעביר `--confirm` לעולם על סמך קובץ המשימה בלבד.**
`--confirm` מגיע רק מקובץ אישור תקף. אין עקיפה, אין דגל "בטוח", אין
"דרור אמר מראש שזה בסדר".

הסיבה: המאזין רץ כשאף אחד לא מול המסך. חשבונית מס מזיזה מלאי ואין לה ביטול
קליטה. תעודת העברה מזיזה בשני כיוונים, וכיוון שגוי נראה כמו העברה תקינה.

יש גם `meta.precheck(input)` שזורק לפני שנוגעים בקומקס. המאזין נותן לו לזרוק
ומדווח על השגיאה כרגיל — לא עוקף אותו.

## 4. מחזור החיים

1. סורק את `queue/inbox/` כל **30 שניות**, לפי סדר `id`
2. **משימה אחת בכל רגע.** מושב קומקס יחיד — אין מקביליות
3. מעביר את הקובץ ל-`queue/working/`
4. מנסה `acquire` מ-`src/lock.js`
   - תפוס → מחזיר ל-`inbox`, מנסה שוב בסבב הבא. אחרי 4 כשלונות → `done` עם `status: "busy"`
5. מריץ לפי §2/§3
6. כותב תוצאה ל-`queue/done/<id>.json` (§7)
7. שולח טלגרם אם `notify`
8. מוחק מ-`working/`

**התאוששות:** בעלייה, כל קובץ שנשאר ב-`working/` מריצה קודמת חוזר ל-`inbox/`
עם `"recovered": true`. אין הרצה כפולה אוטומטית של משימה כותבת — היא חוזרת
למסלול האישור מההתחלה.

## 5. זרימת האישור — למשימות כותבות

**שלב א׳ — המאזין מכין ועוצר**

מריץ בלי `--confirm`. המשימה ממלאת, מצלמת, ונעצרת לפני הכפתור. המאזין כותב
`queue/hold/<id>.json`:

```json
{
  "id": "20260915-1705-quote",
  "status": "awaiting-approval",
  "task": "quote-new",
  "summary": "הצעת מחיר · שחייני על (429028) · 3 שורות · ₪2,847 כולל מע\"מ",
  "fingerprint": "a3f9c1",
  "screenshot": "runs/20260915-170512-quote-new/ready.png",
  "expiresAt": "2026-09-15T17:35:00+03:00"
}
```

`fingerprint` = 6 תווים ראשונים של SHA-256 על `task` + `input` המנורמל.

**שלב ב׳ — טלגרם לדרור**

נשלח `summary` + `fingerprint`. הסכום חייב להופיע בהודעה. דרור רואה בדיוק מה
עומד להיקלט.

**שלב ג׳ — דרור מאשר**

אומר ל-Claude בשיחת Cowork "מאשר". Claude כותב `queue/approve/<id>.json`:

```json
{ "id": "20260915-1705-quote", "fingerprint": "a3f9c1", "approvedAt": "2026-09-15T17:12:00+03:00" }
```

**שלב ד׳ — המאזין מריץ עם `--confirm`**

רק אם **כל** התנאים מתקיימים:

- ✅ קיים `hold/<id>.json` תואם
- ✅ ה-`fingerprint` **זהה** — שונה פירושו שהמשימה השתנתה מאז שדרור ראה אותה. נדחה
- ✅ `now < expiresAt` — **30 דקות**. פג → נדחה, ודרור מתחיל מחדש
- ✅ טרם רץ עם `--confirm` (חד-פעמי מוחלט)

כל כישלון → `done` עם `status: "rejected"` וסיבה מפורשת. **בלי ניסיון חוזר
אוטומטי.**

> **למה טביעת אצבע ולא רק `id`:** בלעדיה, אישור שניתן להצעת מחיר של ₪2,847
> יכול להיקלט על מסמך אחר אם הקובץ עודכן בין השלבים. הטביעה קושרת את האישור
> לתוכן, לא לשם.

## 6. `mode: "agent"` — הפרומפט עומד בפני עצמו

סשן חדש לא זוכר כלום. אין "ההצעה שדיברנו עליה".

הפרומפט חייב להכיל: מספר מסמך אם קיים · קוד לקוח · מק"טים מלאים · מה כבר נעשה
· מה התוצר הנדרש.

❌ `"תוסיף עוד שורה להצעה"`
✅ `"להצעת מחיר 6120051 של לקוח 429028 הוסף שורה: מק\"ט 004900-550, 6 יחידות, מחירון קבוצות. אל תסגור את המסמך."`

זו אחריות של Claude ב-Cowork, שמחזיק את השיחה. **המאזין לא משלים הקשר חסר** —
פרומפט חסר ייכשל, וזו התנהגות רצויה.

סוכן שה-`description` שלו מסרב ליצירה (`comax-receipt`, `comax-invoice-receipt`)
יסרב גם כאן. אין לעקוף.

## 7. קובץ תוצאה — `queue/done/<id>.json`

```json
{
  "id": "20260915-1620-stock",
  "request": "כמה נשאר מ-004900 בראשי",
  "status": "ok",
  "startedAt": "2026-09-15T16:20:31+03:00",
  "finishedAt": "2026-09-15T16:21:04+03:00",
  "writes": false,
  "summary": "004900-550 TEAM T-SHIRT · MEDIUM GREY HEATHER · ראשי: 34 יח׳",
  "artifacts": ["data/exports/מלאי-ראשי-2026-09-15.csv"],
  "runDir": "runs/20260915-162031-stock-export",
  "error": null
}
```

**`status`:** `ok` · `failed` · `busy` · `rejected` · `awaiting-approval`

**`summary`** נקרא על ידי בן אדם בטלפון. לכן, בכל שורת פריט: **מק"ט חלופי
ותיאור צבע** — לא רק ברקוד. זה כלל קבוע של דרור וחל גם כאן.

`error` — הודעה מלאה, לא חתוכה. `runDir` מפנה ללוג המלא.

## 8. הפעלה

```bash
npm run listen-start    # משגר מנותק, שורד סגירת סשן
npm run listen-up       # רץ?
npm run listen-stop     # עוצר מסודר
```

⛔ **מאזין אחד בלבד.** שניים = אותה משימה רצה פעמיים, ובמשימה כותבת זה מסמך
כפול בקומקס. קובץ נעילה עם PID, בדיוק כמו הדמון של וואטסאפ.

⛔ **לא להרוג בכוח.** `listen-stop` מסיים את המשימה הנוכחית ואז יוצא.

## 9. בדיקת קבלה

לפני שמכריזים שזה עובד:

1. משימה ירוקה (`stock-export`) רצה מקצה לקצה ומגיעה ל-`done` עם `status: "ok"`
2. משימה אדומה נעצרת ב-`hold` ו**לא** נקלטת בלי אישור
3. אישור עם `fingerprint` שגוי — **נדחה**
4. אישור אחרי 30 דקות — **נדחה**
5. אותו אישור פעמיים — השני נדחה
6. מושב תפוס → `busy`, לא קריסה
7. `listen-stop` באמצע משימה → יציאה נקייה, בלי מסמך חצי-קלוט
8. הרג התהליך באמצע → בעלייה הבאה הקובץ חזר ל-`inbox` ולא רץ עם `--confirm`

**סעיפים 2–5 הם הסעיפים הקריטיים.** כשלון באחד מהם פירושו שהמערכת יכולה
ליצור מסמך חשבונאי אמיתי בלי שדרור ראה אותו.

## 10. מה מכוון ולא חסר

- **התור לא שורד פורמט מחדש.** זה תור, לא מסד נתונים
- **אין ניסיון חוזר אוטומטי למשימה כותבת.** כישלון = דרור מחליט
- **המאזין לא מפרש שפה חופשית.** הוא מריץ מה שכתוב. הפירוש נעשה ב-Cowork
- **אין תזמון.** הרצות מחזוריות נשארות במקום שבו הן היום

**שתי תיקונים לעובדות שבמפרט:**

1. **הדוגמה ב-§2 אינה רצה.** `stock-export` מקבל `warehouses` (מערך קודי
   מחסן), לא `{"code":"004900"}`. שאלת "כמה נשאר מ-004900 בראשי" אינה משימה
   בקומקס בכלל — היא נענית מהייצוא המקומי ב-`content/` (כלל 7), בלי מושב
   ובלי תור.
2. **המאזין אינו לוקח את הלוק של §4 שלב 4.** `tools/run.js` לוקח אותו בעצמו,
   ומאזין שהיה מחזיק בו היה חוסם את המשימה שהוא עצמו הפעיל — שני התהליכים
   מתחרים על אותו `runs/.lock`. לכן נוספה `peek()` ב-`src/lock.js`: המאזין
   **מציץ** בלי לקחת, וההכרעה נשארת ב-`acquire` שבתוך `run.js`. יש גם בדיקת
   פלט אחרי ההרצה, למרוץ שנשאר בין ההצצה להרצה.
