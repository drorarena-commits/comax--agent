# מפת מערכת קומקס

המפה נכתבת ביחד, מסך אחרי מסך. לכל מסך יש `knowledge/screens/<שם>.json` (סלקטורים מדויקים),
`.txt` (גרסה קריאה) ו‑`.png` (צילום).

## מה למדנו עד עכשיו

המערכת היא **שתי שכבות**:

| שכבה | טכנולוגיה | כתובת |
|---|---|---|
| התחברות | ASP.NET (`.aspx`) | `https://www.comax.co.il/COMAX_WEB/LogInComax/LogInWeb.aspx` |
| האפליקציה עצמה | **Max2000** — ASP קלאסי, frameset עם ~56 frames | `https://www.comax.co.il/Max2000/Max2000_run_G.asp?p=0\|<טוקן>\|<קוד>\|<תאריך>` |

### שני ממצאים שמעצבים את כל הארכיטקטורה

**1. כתובת האפליקציה מכילה טוקן סשן.** ה‑`p=0|wmkzybfgf|zdbg|01/09/2026_14:02:02` משתנה
בכל התחברות. המשמעות: **אי אפשר לשמור כתובת ישירה לשום מסך.** כל ניווט חייב לעבור דרך
התפריטים החיים של המערכת. כל המשימות ייבנו כך.

**2. הסשן לא שורד סגירה של הדפדפן.** נבדק: נסגר חלון, נפתח מחדש → חזרה למסך התחברות.
אין "זכור אותי" בטופס. המשמעות: או שמשאירים את חלון הסוכן פתוח לאורך היום, או שמכניסים
את פרטי ההתחברות ל‑`.env` להתחברות אוטומטית.

## הערות טכניות

- כלי המיפוי (`src/inspect.js`) סורק את כל ה‑frames, לא רק את העמוד הראשי — הכרחי כאן.
- התוויות בעברית יושבות ב‑`td` הסמוך (RTL) או ב‑`value` של השדה. כלי המיפוי קורא משניהם.

  בפרופיל. נאמת מול `FramePrintSend` כשנגיע לדוחות.

## שני דפוסי התנהגות קריטיים

**1. שדות לקוח/פריט נפתרים ב־Enter, לא בהקלדה.**
הקלדה של `"וינגייט"` לבד לא עושה כלום. `Enter` משלים אוטומטית ל־`"אגודת הסטודנטים בוינגייט"`.
כל שדה חיפוש כזה חייב `type()` ואז `press('Enter')`.

**2. חלונות קופצים לא צפויים.**
ברגע שנבחר לקוח עם הערות, נפתח אוטומטית חלון `הערות` (`Max2000_NET_2022/Lk/_IdxRemarksU.aspx`)
מעל הטופס וחוסם אותו. חייבים לסגור אותו לפני שממשיכים. כל משימה צריכה לטפל בזה.

## מוסכמות שחוזרות בכל המערכת

- **`#OK` / `#Cancel`** — אישור/ביטול בכל דיאלוג (✓ ירוק / ✗ אדום)
- **`#DoClose` / `#DoExit` / `#DoMinMax` / `#DoPrint` / `#DoHelp`** — בקרות חלון
- שמות ה־frames של תוכניות הם `f0`, `f1`, `f2`... **לפי סדר הפתיחה, לא לפי תוכנית.**
  אחרי סגירה הם הופכים ל־`Blank_Screen.htm`. אף פעם לא לקודד שם frame קשיח —
  להשתמש ב־`activeFrames()` / `openProgram()`.
- כפתורי הסרגל הם `<button>` בלי טקסט; התווית ב־`title`. לטרגט לפי `id`.

## תיקונים — טעויות מיפוי שהתגלו בהרצה חיה

ארבע מלכודות שנראו נכון במיפוי הסטטי והתבררו כשגויות בפועל. כולן מאותו סוג:
**האלמנט קיים ב־DOM אבל אינו מה שהוא נראה.**

### 1. `#chg` הוא מחליף *סוג לקוח*, לא בורר

מיפיתי אותו כ"בורר לקוח" כי ה־`title` שלו היה `לקוח:`. בפועל: `chg_onclick()` מחליף
בין `לקוח` ל־`לקוחות שיווק`, ומחליף את השדה הפעיל מ־`#IdxLk` ל־`#IdxH`.
**אין ללחוץ עליו.** דרור לא משתמש ב"לקוחות שיווק" בכלל.

### 2. הבורר האמיתי — `#CcomboBut<שם השדה>`

דפוס קבוע בכל המערכת: `#CcomboButIdxLk`, `#CcomboButStore`, `#CcomboButMhr`,
`#CcomboButSochen`, `#CcomboButSwIzur`, `#CcomboButIdxPrj`.
`fillLookup()` גוזר אותו מה־id של השדה — אין צורך לציין.

### 3. מספר המסמך הוא `<span id="DocId">`, לא input

`#DocNo` הוא input **ריק**. המספר המוקצה (6120041) יושב כטקסט ב־`#DocId`.

### 4. שני frames קבועים ומוסתרים שנראים כמו חלונות פתוחים

| frame | האמת |
|---|---|
| `System/Select/Select_G.htm` | frame **קבוע** בגודל 2x2 עם `visibility:hidden`, ששומר את כתובת החיפוש האחרון |
| `Server/Hov_MsgScreen.asp` | frame קבוע, לא חלון קופץ |

**זיהוי לפי כתובת בלבד מחזיר "פתוח" לחלון שנסגר מזמן.** `isPickerVisible()` בודק את
האלמנט במסמך האב — גודל, `visibility`, `display`. זה גרם לבאג האמיתי: הקוד לחץ על שורה
בבורר ישן ובחר את הרשומה הלא נכונה.

### 5. השלמה ב־Enter: אי אפשר לבדוק "האם הערך השתנה"

כששם ההזנה כבר מדויק ("מכבי אשדוד"), Enter פותר אותו אבל הערך נשאר זהה — והבדיקה
`resolved !== value` מדווחת כישלון. **המבחן הנכון: האם המערכת פתחה בורר.**
אם לא נפתח בורר והשדה מלא — נפתר.

## מה עובד מקצה לקצה (מאומת)

```bash
node tools/run.js quote-new --json '{"customer":"מכבי אשדוד","details":"..."}'
```

פותח הצעות → הוספה → מקליד לקוח + Enter → קורא מספר הצעה → ממלא פרטים →
**עוצר לפני `#OK`** ומצלם. אומת: הצעה 6120041, לקוח מכבי אשדוד (112419),
מחסן "ראשי" ומחירון "מכירה ראשי" נמשכו אוטומטית מכרטיס הלקוח.

**מה שחסר:** מסך שורות הפריטים, שנפתח רק אחרי `#OK`.

### 6. הבורר מסנן לפי מה שכבר בשדה (טיפ של דרור)

לחיצה על החץ (`#CcomboBut<שדה>`) **לא מציגה את כל האפשרויות** — היא מסננת לפי הערך
שכבר יושב בשדה. כשקראתי את `#Mhr` עם "מכירה ראשי" בפנים קיבלתי **מחירון אחד** והסקתי
בטעות שזה כל מה שקיים. בפועל יש **שלושה**.

**כדי לקרוא רשימה מלאה חייבים לרוקן את השדה לפני פתיחת הבורר.**
זה מה ש-`tools/read-options.js` עושה (ומחזיר את הערך המקורי אחריו):

```bash
npm run options -- Mhr      # מחירונים
npm run options -- Store    # מחסנים
```

## מחיר סיטונאי: שתי דרכי הזנה, אותו כסף

**הכלל הוא על הנטו: `round(ברוטו / 2)`.** דרך ההזנה משתנה לפי משטר המחירון.

| | מחירון לפני מע"מ | מחירון כולל מע"מ |
|---|---|---|
| `#Mhr` | `round(ברוטו/2)` | לא נוגעים — נשאר הברוטו |
| `#AczDis` | 0 | `(1 − יעד × (1+מע"מ) / ברוטו) × 100` |
| שורה | 145.00 | 171.10 |
| **סה"כ לתשלום** | **171.00** | **171.00** |

**האחוז נגזר מהיעד המעוגל ולא קבוע.** ל-289.90 ב-18% זה **40.98%** ולא 41.00%:
הכלל מעגל לשקלים שלמים, ואחוז קבוע היה נותן נטו 144.95 מול 145.00 בדרך השנייה.
`wholesaleDiscountPct()` ב-`src/catalog/pricing.js`.

**41% על מחירון כולל מע"מ הוא החתימה של סיטונאות, לא חריגה.** דווח פעם לדרור
כ"41% הנחה חריגה", ואז "תוקן" ל"בעצם חצי מהברוטו" — שתי האמירות מתארות את אותו
מחיר, והתיקון היה הטעות. `1 − (1+מע"מ)/2` = 41.0% ב-18%, 41.5% ב-17%.

**מה שזה שבר בצד הכתיבה:** `pricing.js` הצהיר "מחיר סיטונאי תמיד נכנס לפני מע"מ",

## טיוטה שלא הופקה נתפסת מחדש

`quote-new` על לקוח שיש לו הצעה **לא-קלוטה** לא יוצר מסמך חדש — הוא חוזר לאותו
מסמך ומחליף לו את הכותרת. כך 6120045 עברה ממחירון קבוצות למכירה ראשי באמצע בדיקה,
והצלע הראשונה נמחקה בלי שנאמר דבר.

**כל בדיקה שמייצרת שני מסמכים לאותו לקוח חייבת להפיק (`quote-finalize`) את הראשון
לפני שהיא מתחילה את השני.** אחרי ההפקה `quote-new` נתן 6120046 כמצופה.

הצד השימושי של אותו מנגנון: אפשר לתקן כותרת של טיוטה פתוחה בהרצה חוזרת של
`quote-new` עם הערכים הנכונים.

`quote-finalize` בלי `docNo` לא תמיד מזהה את מספר המסמך ואז לא מפיק PDF. במקרה כזה
מריצים שוב עם `{"pdfOnly":true,"docNo":"..."}`.
