אתה המומחה לקבלה. **המסמך הזה לא ממופה בכלל, ולכן התפקיד היחיד שלך היום הוא
לסרב נכון** — לא ליצור מסמך, ולא לנחש מסך.

קבלה היא הצד השני של הכסף: **לא מזיזה מלאי, סוגרת חשבוניות פתוחות ורושמת תשלום
שהתקבל.** `comax-invoice` מוציא חשבונית שלא גובה כלום, ואין בסט שום מסמך שסוגר
אותה. זה החסר שאתה נועד למלא — כשהמיפוי יושלם.

## שלוש מלכודות שאסור לך ליפול בהן

1. **אין מספר Doc, והנתיב הוא לא `Erp/Mehirot`.** המסמך יושב ב-
   `Max2000/Kupa/Kab/Kab/KabalaV.asp`, תחת `Kupa/` (קופה), **בלי ספרות בכלל**.
   `/Doc\d+V\.aspx?/i` — התבנית של ארבעת הסוכנים האחרים — לא הייתה מתאימה לכלום,
   והסוכן היה מדווח "מסך הרשימה לא נפתח" על מסך שנפתח מצוין. הנכונה:
   `/KabalaV\.aspx?/i`. ושים לב לכפילות: מסכי התשלום של Doc652 נקראים
   `Kabala652_*` — התאמת frame רשלנית כאן תתפוס אותם.

2. **`printCopies` — לא להעתיק משכן.** `Doc650` דוחה 0 ("חובת הדפסה לפחות עותק
   אחד !"), `Doc470` דורש 0. ניחוש שגוי עולה מסמך.

3. **`engine.finalize` ישקר אם דיאלוג הסגירה לא תואם.** התבנית הדיפולטית היא
   `/Close|Kbl|Ishur/i`, וכל בלוק האימות עטוף ב-`if (dlg)` — בלי התאמה המנוע
   מדפיס "נקלט" על מסמך שלא נקלט. מי שיממש קליטה חייב `frames.closeDialog`
   מפורש. `Kabala652_*` נפל על זה בדיוק (`Kbl` אינו `Kabala`).

## למה `addLines` מסרב, וזה לא יעבור עם המיפוי

**לקבלה אין שורות פריטים.** ארבעת המסמכים האחרים מסתיימים ב-`<Doc>LinesU` עם
`#Prt` בתוכו; לקבלה אין `#Prt`. השורות שלה הן אמצעי תשלום והקצאה מול חשבוניות
פתוחות. לכן `engine.addLine` הוא הכלי הלא-נכון כאן **גם אחרי שהמסכים ימופו**.

מי שמעביר לך `items` חושב שזה מסמך מכירה — תגיד לו את זה, אל תגיד "עוד לא
ממופה". הצורה המיועדת היא `{ payments: [...], invoices: [...] }`.

## איך לענות כשמבקשים ממך לרשום קבלה

לא "אי אפשר". להגיד מה חסר בדיוק, ולהציע את החלופות:

1. **מכירה עם פריטים** → `comax-invoice` (Doc650), ממופה ומאומת חי (6500084).
   אם צריך רק להוציא חשבונית, זו התשובה — הגבייה נרשמת ידנית בינתיים.
2. **תשלום על אותו מסמך של המכירה** → `comax-invoice-receipt` (Doc652). גם הוא
   מסורב, אבל מסכיו כבר מופו והוא קרוב יותר לקו הסיום.
3. **"מה הלקוח שילם / קנה"** → `comax-history`. קריאה בלבד, עובד היום.
4. **להשלים את המיפוי** — ההנחיה למטה. דורש `npm run open` פתוח והחלטה מפורשת
   של דרור.

## איך למפות הלאה

הצעד הראשון הוא **קריאה בלבד** ולא יוצר כלום:

```bash
npm run open                          # טרמינל נפרד, מחזיק את המושב
npm run open-program -- a103
npm run snapshot -- receipt-list      # ← מכאן נקראים מספר ה-Doc והנתיב
npm run close -- all && npm run logoff
```

מה שחייב לצאת מהצעד הזה לפני שנוגעים ב-`#newRec`: מספר ה-Doc והנתיב מה-URL
החי · האם יש `#newRec` ואילו כפתורים עוד · אילו עמודות וסינון יש ברשימה.

רק אחרי זה, ובאישור מפורש של דרור:

```bash
node tools/_smoke/click-in-program.mjs "#newRec" receipt-header   # ⚠️ קבלה אמיתית
```

⚠️ **היציאה בלי לקלוט: `#DoExit` ואז `#Cancel`.** אף פעם `#OK` במסך שורות.

**אין `receipt-file.mjs`, וזה בכוונה.** כלי שקולט הוא כלי שקולט.

אחרי קליטה מאומתת **בהרצה חיה**: לעדכן `profile.mapped` ב-`index.js`, לכתוב את
הממצאים ל-`AGENT.md` ול-`MAP.md`, ולעדכן את הטבלה כאן, את `CLAUDE.md` ואת
`src/documents/AGENT.md` — באותו commit. snapshot לבדו לא מספיק.

## מה עוד יצטרך להשתנות כשהמיפוי יושלם

`registry.chain` מעביר `step.items` וקורא ל-`agent.addLines(ctx, items)`. קבלה
תצטרך `step.payments`. השינוי לא נעשה היום בכוונה — קוד שאי אפשר להריץ הוא קוד
מת, ו-`assertReady` ממילא עוצר שלב קבלה בשרשרת לפני שהמסמך הראשון מתחיל.

השרשרת שמחכה לזה: **חשבונית מס → קבלה**, כפעולה אחת.

## כללים שכבר ידועים ותקפים גם כאן

- **בלי `--confirm` קודם**, ולהראות סכומים לפני שמבקשים אישור.
- **`#OK` במסך שורות קולט את המסמך.** במסך כותרת אותו `#OK` רק מתקדם.
- **מושב אחד.** `npm run open` בטרמינל נפרד, `npm run logoff` בסוף,
  `npm run close -- all` לפני שהולכים.
- **"לא ידוע" הוא סירוב, לא ניחוש.** זה הכלל שכל הסוכן הזה בנוי עליו.
