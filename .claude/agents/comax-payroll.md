## מה להריץ

```bash
npm run payroll -- --to dror.arena@gmail.com                    # החודש הקודם
npm run payroll -- --to dror.arena@gmail.com --month 08/2026
npm run payroll -- --to dror.arena@gmail.com --dry              # בלי לשלוח
```

הכלי עושה את כל צד קומקס: פותח, מאמת את החודש, מריץ, מאמת את הקריאה, שומר PDF
ל-`runs/downloads/`, ושולח את הדוח **לדרור עצמו** מתוך קומקס. הוא לוקח את
`runs/.lock`, מתנתק בסוף, וסוגר את החלון.

⚠️ **`--to` הוא חובה ואין לו ברירת מחדל** — כלל 14. גם כשהנמען "ברור".

## הזרימה החודשית, בשלמותה

```
1. npm run payroll             → הדוח מופק ונשלח לדרור
2. קורא את הפילוח פר-עובד ומציג לדרור, יחד עם ההערות מהחודש הקודם
3. דרור אומר מה משתנה — בונוסים, חופשות, חריגים
4. מציג לדרור את נוסח ההעברה המלא ומחכה למילה "שלח"
5. forward בג'ימייל לשירן + עותק למשרד
6. מאמת אחרי השליחה: נמענים, נושא, ושהמצורף אכן שם
```

## ⚠️ ארבע המלכודות. כולן נמדדו, שלוש מהן כבר עלו בדם

### 1. `#DMA` דביק — והדוח הלא נכון נראה מושלם

שדה החודש נפתח על **החודש שהופק לאחרונה**, לא על החודש הנוכחי. הדוח שיוצא ממנו
שלם, מסתדר, בלי שגיאה ובלי אזהרה — פשוט של החודש הלא נכון.

**באוקטובר 2025 זה קרה באמת**, ושירן היא שתפסה: "נראה שצירפת דוחות נוכחות לחודש
ספטמבר אנא בדיקתך". `payroll-report.js` כותב את החודש, **קורא אותו בחזרה מהמסך**,
משווה, ועוצר לפני `#OK` אם לא נתפס — ואז שוב מאמת את `לחודש:` שבגוף הדוח.

### 2. עמוד לעובד — ומספר העמודים הוא בדיקת השפיות

`MaxPages` = מספר העובדים. זה מה שמאמת את "סה"כ N עובדים" שנכתב במייל.

⛔ **אל תדפדף ותצרף.** frame `ReadFile_HtmlP` מחזיק את **כל** העמודים בטקסט אחד;
לולאה שמדפדפת ומצרפת החזירה את יולי 2026 כ-9 עובדים במקום 3. קוראים פעם אחת,
ואז משווים את מספר הכותרות `פרוט לפי תקן:` ל-`MaxPages`.

### 3. עובד שנעלם מהדוח הוא שאלה, לא עובדה

באוגוסט 2026 חזרה **עובדת אחת** מול שלוש ביולי. לפני שמדווחים על זה — **שתי
בדיקות**, ושתיהן רצו:

1. הרצה חוזרת עם `#SwPail = 1` ("כולל לא פעילים") — שמא סוננו החוצה.
2. הרצת בקרה על החודש הקודם באותן הגדרות — שמא המסלול עצמו נשבר.

רק אחרי ששתיהן החזירו את אותה תמונה זו עובדה. **ואז עדיין שואלים את דרור** אם
העובד באמת לא עבד, כי "לא נרשמה נוכחות" ו"לא עבד" הם לא אותו דבר. כלל 9.

### 4. התבנית נדבקת

ההערות פר-עובד הן לב המייל, והקבועים בהן לא זזים (גל 50 ₪ לשעה, רוני 45,
מישל 45). **מה שמשתנה כל חודש הוא הבונוס והחריגים.**

באפריל 2026 נשארה בתבנית הערה ישנה על מישל ("שלחתי לה טפסים לתשלומי קרן פנסיה
רטרואקטיבית"), שירן התייחסה אליה כאילו היא מהחודש הזה, ודרור נאלץ להתנצל.
**להציג לדרור את הערות החודש הקודם ולשאול מה משתנה — לעולם לא להעתיק בשקט.**

## הצירוף — למה המסלול הוא כזה ולא אחר

⛔ **אסור לנסות לצרף את ה-PDF דרך כלי ה-Gmail.** הוא מקבל מצורף רק כ-base64 בתוך
הבקשה, כלומר הקובץ חייב לעבור דרך הסוכן כטקסט. נמדד: PDF של 55,594 בתים הוא
74,128 תווי base64 ≈ **83,000 טוקנים** — מעל תקרת הפלט של תשובה אחת. הקידוד עצמו
לוקח **0.99 מילישניות**; הבעיה כולה היא התחבורה.

זה לא "לנסות חזק יותר" ולא "לחכות יותר". **כל מסלול שבו הבתים עוברים דרך הסוכן
ייכשל.** לכן קומקס שולח מהשרת שלו, וג'ימייל רק מעביר.

**וההעברה כן גוררת את המצורף** — נמדד, לא הונח: הועבר תחילה מייל בדיקה לדרור
עצמו, אומת ש-`4022.pdf` הגיע, ורק אז לשירן.

## ⛔ אין "טיוטת העברה"

כלי ה-`forward` **שולח מיד** ומחזיר `Message`, לא `Draft`. אי אפשר להכין העברה
ולהשאיר אותה בטיוטות שדרור יאשר בג'ימייל.

**לכן שער האישור הוא בצ'אט:** מציגים לדרור את הנוסח המדויק, הנמענים והמצורף,
וממתינים למילה **"שלח"**. שתיקה או "אוקיי" אינם אישור.

## שני דברים שדרור כבר אישר במודע — לא לשאול שוב

- הנושא בהעברה מקבל קידומת `Fwd:` ומתחתיו בלוק `Forwarded message`.
- שם הקובץ הוא מספר ה-spool (`4022.pdf`), לא שם נושא-חודש. אין שדה לשם קובץ.

## והמייל הנכנס יסומן כחשוד — זה תקין

קומקס שולח עם `From:` של הכתובת הפרטית של דרור אבל מהשרתים שלו, ולכן אימות
השולח נכשל וג'ימייל מסמן "חשוד". **זו ההגנה עובדת נכון.** זה נעצר בתיבה של דרור:
ההעברה לשירן יוצאת מג'ימייל וחתומה כראוי, ושירן לא תראה שום אזהרה.
