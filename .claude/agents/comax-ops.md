# 1. המושב היחיד

לקוד המשתמש בקומקס יש **מושב אחד**. זו המגבלה שמעצבת את כל השאר.

```bash
npm run open          # מצב לימוד — בטרמינל נפרד, נשאר פתוח
npm run check-login   # מחובר או לא
npm run close -- list # מה פתוח בקומקס
npm run close -- all  # סוגר הכל
npm run logoff        # התנתקות מסודרת — משחררת את הסשן בשרת
```

## שלושה כללים שאי אפשר לגלות מקריאת הקוד

1. **סגירת החלון לא משחררת את הסשן.** בקשת השחרור היא
   `Max2000_NET_2022/Server/CloseSession.ashx`, שקומקס שולחת מתוך
   `top.onUnload('fset')` — **אסינכרונית, בתוך unload**. הדפדפן הורג בקשות כאלה
   כשהחלון נסגר, ולכן היא כמעט אף פעם לא יוצאת. גם `#LOGOFF_Prog` לא עוזר: כל מה
   שהוא עושה זה `top.window.close()`, ש-Chrome חוסם ושלא שולח לשרת כלום. לכן
   `logoff()` קורא ל-`onUnload` בעצמו **ומחכה לתשובה**.

2. **"קוד משתמש בשימוש" זה לא כשל — זה סשן תקוע.** יש חלון פתוח → `npm run logoff`.
   אין חלון → **להמתין כ-3 דקות**, השרת משחרר לבד. ההתחברות מנסה שוב לבד
   (`login.busyRetries: 4`, `login.busyWaitMs: 45000`) לפני שהיא נכשלת. אל תרוץ
   להריץ דברים במקביל כדי "לעקוף".

   **מ-03/09/2026 זה אמור לקרות הרבה פחות.** `tools/run.js` ו-`tools/check-login.js`
   קוראים ל-`logoff()` בסוף — אבל **רק על חלון שהם עצמם פתחו** (`session.owned`).
   חלון של `npm run open` שייך לדרור ואסור לנתק אותו מתחתיו. מה שעדיין משאיר
   מושב תפוס: הרג התהליך באמצע (Ctrl+C על משימה, קריסה), ואז `npm run logoff`
   או להמתין.

   ⚠️ **הבדיקה הראשונה היא חלון כרום כפול, לא הקוד ולא ה-`.env`** (12/09/2026).
   "להמתין 3 דקות" נכון רק כשאין חלון: **חלון פתוח מחזיק את המושב לצמיתות**, כי
   הפריים-סט מתשאל את השרת כל ~90 שניות (ממצא 3 ב-MAP.md). באותו יום רצו חמישה
   ניסיונות התחברות לאורך 4.5 דקות — כולם נידונו מראש — עד שדרור אמר "היה חלון
   כפול פתוח". לאיתור, ובלי לגעת בכרום האישי של דרור:
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" |
     Where-Object { $_.CommandLine -like "*AGENT-COMAX-CLOAD*" }
   ```

   ⚠️ **ומושב תפוס אינו רושם יותר חסימה.** עד 12/09/2026 `login()` החזיר `false`
   גם על "קוד משתמש בשימוש" וגם על סיסמה שגויה, ו-`ensureComax` רשם
   `runs/.login-blocked` על שניהם — כלומר **30 דקות שיתוק** על תקלה שנפתרת
   בסגירת חלון. עכשיו `lastLoginFailure()` מבדיל, והחסימה נרשמת רק על סיסמה
   שקומקס דחה. אם בכל זאת נתקלת בחסימה שגויה, לשחרר דרך ה-API ולא במחיקת קובץ:
   ```bash
   node -e "import('./src/ensure-comax.js').then(m=>console.log(m.clearBlock()))"
   ```

3. **`npm run open` צריך לרוץ בטרמינל נפרד** בזמן שממפים או מריצים משימות. שאר
   הכלים מתחברים לאותו חלון דרך פורט 9222. `open` מתחבר לחלון קיים במקום לפתוח
   שני ולהתנגש עם עצמו.

**חלון פתוח בולע את הדאבל-קליק של המשימה הבאה.** `npm run close -- all` בסוף כל
רצף — זו מוסכמה של דרור, לא ניקיון.

# 2. רענון הייצוא המקומי

`comax-stock` עונה מ-`content/` ולא נוגע בקומקס. **אתה זה שממלא את `content/`.**

| פקודה | מה עושה | זמן | נוגע בקומקס |
|---|---|---|---|
| `npm run stock-matrix` | דוח יתרות מלאי → `data/exports/` | ~2.5 דקות | כן |
| `npm run full-stock` | 11 מנות לפי טווחי מק"ט → `stock-full.json` | **~25-30 דקות** | כן |
| `npm run merge-full` | מצליב עם הקטלוג → `content/מלאי-מלא-<תאריך>.csv` | שניות | לא |
| `npm run apply-matrix` | צורב מטריצה על מלאי-מלא קיים | שניות | **לא** |
| `npm run run -- items-export` | **קטלוג הפריטים** לאקסל → `data/exports/` — ברירת מחדל **רזה**, רק עמודות עם תוכן | ~60 שניות | כן |
| `... --json '{"fields":"all"}'` | ⚠️ 97 עמודות, 58MB. **חריג בלבד** — לא לייצא הכל כברירת מחדל | ~70 שניות | כן |

## ייצוא הפריטים המלא — `items-export`

מסלול אחר לגמרי מדוח המטריצה: `a84` (פריטים) → לשונית **נוספים** → **יצוא
לאקסל**. אין תקרת 1500 שורות ואין חלוקה למנות — **כל 13,107 הפריטים בהרצה
אחת של פחות משתי דקות**. זו הדרך להביא ברקוד · קוד חלופי · מחלקה · קבוצה ·
דגם · צבע · מותג · ספק · עלות — דברים שדוח המטריצה לא נותן בכלל. קריאה בלבד.

**ברירת המחדל היא רזה: 36 תיבות ⇒ 37 עמודות, 22 MB.** בלי ארגומנטים בכלל.
הרשימה נמדדה ולא נוחשה — הרצת `fields:"all"` של 07/09/2026 הוציאה 101 עמודות
ב-58 MB, ומהן **45 היו ריקות בכל 13,107 השורות**, שלוש החזיקו ערך קבוע יחיד
("לא" ב-שקיל · מעדניה · נמכר באילת), ושלוש היו העתק מדויק של עמודה אחרת
(`יתרת מלאי` ו-`יתרת מלאי לחברות` זהות ל-`מלאי`; `שם חלופי` זהה ל-`שם פריט`
ב-98.7% מהשורות שיש בהן ערך). דרור: "חבל על המשקל המיותר של הקובץ."

`{"fields":"all"}` נשאר לשדה נדיר, ו-`{"fields":["SwBarkod",...]}` לרשימה
מדויקת. **עמודה אחת ריקה שורדת גם ברזה** — `מחיר מחירון 2` מגיעה כרוכה עם
`מחיר מכירה` ואי אפשר לכבות אותה בדיאלוג.

שלוש מלכודות, כולן נאכפות ב-`src/tasks/items-export.js`:

1. **תיבות הסימון לא עושות כלום עד `GetMiunVal()`.** לתיבות בפריים `FMiun` אין
   `onclick`; מה שנשלח לשרת הוא שדות טקסט באותם ids בפריים האב, ורק
   `OK_onclick` מסנכרן ביניהם. אפשר לסמן 97 תיבות, לראות אותן מסומנות, ולקבל
   קובץ עם העמודות של הפעם הקודמת. המשימה קוראת ל-`GetMiunVal()` בעצמה (היא
   רק מעתיקה, לא שולחת) ומאמתת מול שדות הטקסט **לפני** הקליק.

2. **תחומי הסינון דביקים בין הרצות.** נמצא `Store_MlayM=15` שנשאר מ-
   `stock-export` של מחסן 15 מיום אחר — קובץ כזה נראה כמו קטלוג מלא ומכיל
   מחסן אחד. המשימה מנקה את כל 33 התחומים וקוראת אותם בחזרה.

3. **הקובץ הוא HTML ב-windows-1255 בתחפושת `.xls`, 58 MB, ולא נפתח באייפון.**
   להמיר ל-CSV ב-UTF-8 עם BOM (יוצא 5.3 MB) ולהעתיק ל-`content/`.

⛔ **אין בקובץ מחיר ברוטו לצרכן** — עמודת המחיר היא המחירון שנבחר בשדה `Mhr1`
(ברירת מחדל `1 - מכירה ראשי`), שהוא הנטו שאחרי ההנחה הסטנדרטית. הברוטו, שהוא
הבסיס לנוסחת הסיטונאות, אינו אחת מ-97 האפשרויות ואינו יוצא מכאן.

## חמישה כללים שאי אפשר לגלות מקריאת הקוד

1. **הדוח נעצר ב-1500 שורות, והתקרה היא על שורות פריטים ולא על מחסנים.** הרצה
   עם שני מחסנים במקום חמישה החזירה בדיוק אותם 1500. לכן `full-stock` חותך לפי
   **טווחי קוד פריט** מ-`data/item-ranges.json`. הדוח ממיין מספרית
   (1, 10, 11, 93, 1111…), לא כטקסט, והטווחים נחתכים כך.

2. **סריקה שנקטעה ממשיכה, לא מתחילה מחדש.** כל מנה נשמרת בנפרד ב-
   `data/exports/chunks/`, והאיחוד קורה רק בסוף: `npm run full-stock -- --from 3`.
   אחרי חצי שעה של הרצה אל תתחיל מאפס בגלל מנה אחת.

3. **`apply-matrix` הוא הדרך הזולה, ולא נכנס לקומקס בכלל.** הגיעה מטריצה חדשה?
   לצרוב אותה על מלאי-מלא קיים במקום לרוץ סריקה מלאה. **רץ יבש כברירת מחדל**;
   `-- --write` כותב. הקובץ הקודם לא נמחק — הקוראים בוחרים את החדש לפי mtime.

4. **פריט שלא במטריצה נשאר בדיוק כמו שהוא — כולל אפסים ומינוסים.** `משלוח` ב-‎-529
   הוא יתרה אמיתית, ו"תיקון" שקט ל-0 היה מסתיר אותה. המטריצה מסוננת ל"מלאי מעל 0",
   ולכן היעדרות ממנה היא `≤0 במחסנים שהדוח כיסה` — **לא "0 בכל מקום"**.

5. **בייצוא המטריצה כל עמודות המחסנים נקראות "מלאי", והסדר אינו סדר הקונפיג.**
   הייצוא של 2.9.26 יצא ראשי · רמת גן · מכולה וינגייט · WIX · ספורט & מור רמלה,
   בעוד שהקונפיג שולח 1 · 15 · 3 · 13 · 16 — מי שהריץ בחר את המשבצות. הקוד
   **מכייל** מול הייצוא המלא בכל טעינה ומסרב אם הכיול לא נקי. **אל תקבע סדר קשיח
   ואל תרכך את הסירוב** — לקרוא "ספורט & מור רמלה" מעמודה שהיא "ראשי" נראה תקין
   לגמרי בעין.

**הרצת דוח היא החלטה של דרור, לא שלך.** היא תופסת את המושב היחיד לדקות ארוכות
ומפילה את הכרום. להציג את העלות (2.5 דקות / חצי שעה), להציע את החלופה הזולה
(`apply-matrix`), ולחכות לאישור.

# 3. מיפוי מסכים חדשים


`snapshot` כותב שלושה קבצים: `.json` (מתכון הסלקטורים), `.txt` (תקציר קריא)
וצילום מסך. הוא דורש ש-`npm run open` ירוץ בטרמינל אחר.

## ארבעה כללים

1. **`profile.mapped` נשאר `false` עד שהוכח בהרצה חיה.** זה הבלם של
   `assertReady`, שעוצר **לפני הקליק הראשון** במקום להשאיר מסמך פתוח בקומקס בלי
   שורות. לסמן `true` על סמך snapshot בלבד = להסיר את הבלם.

2. **`#newRec` יוצר מסמך אמיתי.** מיפוי מסך כותרת מתחיל ביצירת מסמך. היציאה היא
   `#DoExit` ואז `#Cancel` — אף פעם `#OK`.

3. **frame לפי path בלבד.** `Doc652` יושב תחת התיקייה של `Doc650`
   (`Erp/Mehirot/Doc650/InvKab_Mlay/Doc652V.asp`), ו-`Doc470U.asp` נושא
   `SwNoClose=0` בשורת השאילתה — התאמה רחבה תפסה את הכותרת במקום את הדיאלוג
   ודיווחה "המסמך לא נקלט" על מסמך שנקלט. לגזור קידומת מה-URL, לא להניח.

4. **ממצא מהרצה חיה נכתב ל-`MAP.md` ולסוכן הרלוונטי, באותו commit.** `MAP.md` הוא
   734 שורות של דברים שנלמדו בדם. מה שלא מתועד — נגלה מחדש, בדרך כלל על מסמך אמיתי.
   **"הסוכן הרלוונטי" הוא שתי שכבות:** `.claude/agents/*.md` (מה שסוכן Claude

   לפני שהוא משנה פונקציה). ממצא שיושב רק באחת מהן ייעלם מהשנייה.

## 💣 `program:` — לא להוסיף בלי אימות זרימה מלאה (06/09/2026)

`openProgram` בוחרת מסלול לפי אופרנד יחיד: האם `program` truthy. מסלול הנתיב
(`top.S.runProgram`) מהיר פי 10 — אבל **הוא לא משחזר את הפרמטרים הספציפיים למסך
שהאייקון בשולחן מעביר**, רק את פרמטרי הסביבה.

ב-a164 החסר היה `SwLk=1`, **והנזק הופיע שלושה שלבים מאוחר יותר**: המסך נפתח
ב-2.5 שניות ונראה תקין לגמרי, טופס הכותרת נפתח, מספר המסמך הוצג — ורק שדה
הלקוח `#IdxLk` נשאר **מוסתר** עד timeout של 30 שניות, בלי שום קשר גלוי לפתיחה.

**התהליך להוספת `program` למסך חדש:**

1. לפתוח פעמיים ולהשוות URL: `npm run open-program -- <id>` (שולחן) מול
   `npm run open-program -- <id> <path>` (נתיב). לרשום כל פרמטר שקיים רק באחד.
2. `runProgram` מקבל query string — קומקס עצמו עושה זאת. להוסיף לנתיב את מה
   **שנמדד**, לא מה שנראה דומה במסך אחר.
3. **לאמת בזרימה מלאה, לא ב"המסך נפתח".**

⚠️ **המלכודת לא גורפת.** a157 (`Max2000_NET_2022`) לא זקוק לדגל; a164
(`Max2000` הקלאסי) כן. חשד ראשוני: מסכי ה-ASP הישנים. **לא כלל — לבדוק כל מסך.**

⚠️ **ולמסכים מסוימים אין מסלול שולחן בכלל.** `open-program -- a157` בלי נתיב
נכשל — האייקון ירד מהשולחן. שם אי אפשר להשוות URLs, והזרימה המלאה היא הבדיקה
היחידה.

⚠️ **נתיב שגוי איטי יותר מלא למסור `program` בכלל:** `waitForProgram` ממצה
`settle` + 4 `think` (~10–17.5s) ואז נופל לשולחן — בנוסף.

עדיין בלי `program`: `transfer` (a111) · `invoice-receipt` (a132) · `receipt` (a103).

חזר לכרום הרגיל **בלי לגעת באף תוסף** — וגם שם הכול היה תקין. חסימת תוסף היא
דטרמיניסטית, ולכן היא כנראה **לא** הייתה הסיבה. המועמד המוביל: כשל טעינה זמני
שנשמר במטמון והתנקה.

⛔ **וסתר הוא לא בדיקה מבחינה** — לחלון סתר יש מטמון **נפרד וריק**, אז הוא מכבה
תוספים *וגם* מאפס מטמון. הוא עונה רק "מקומי או לא", לא *למה*. אל תציג אותו
כהוכחה לתוסף — זו בדיוק הטעות שנעשתה כאן.

**אם זה נעלם מעצמו — לא עושים כלום.** אין מה לתקן כשאין מה לשחזר.

דרור שאל על זה מהסס, כי הוא חשש שמשהו בחשבון שלו נשבר. **זו לא תקלת קומקס
ולא הרשאות.** הריבוע עם הפינה הקרועה הוא ה-placeholder של Chrome ל"התמונה לא
נטענה" — לא אייקון של קומקס. השרת מגיש את אותו HTML לכל דפדפן.

בסיס ההשוואה הידוע-תקין: `knowledge/screens/home-0902.png` — אותו שולחן עבודה,
אותו קוד משתמש, מדפדפן הסוכן, כל 52 האייקונים תקינים. דפדפן הסוכן הוא Chrome
תקני על פרופיל **בלי אף תוסף**, בלי דגלי אבטחה מרופפים.

**מה שכן בטוח:** תקלת שרת מפילה את הכול ובכל דפדפן, ולכן תת-קבוצה שנופלת בעוד
אחרים עוברים אומרת שהמקור **מקומי**. היא *מתיישבת* עם חסימה לפי דפוס שם קובץ,
אבל גם עם כשל זמני בחלק מבקשות התמונה — זו אינדיקציה, לא הכרעה.

**שני צעדי האבחון שמוסרים למי ששואל** — רק צעד 2 מכריע:

1. **חלון סתר** (`Ctrl+Shift+N`) — צעד ראשון זול שעונה "מקומי או לא", אבל
   **לא אומר למה**: הוא מכבה תוספים *וגם* מאפס מטמון.
   ⚠️ **זו כניסה שנייה לאותו קוד משתמש** — `npm run logoff` קודם, אחרת קומקס
   יענה "קוד משתמש בשימוש" (כלל 1, המושב היחיד).
2. **זה מה שמכריע:** `F12` → **Network** → סינון **Img** → `Ctrl+Shift+R`.
   `blocked:other` = תוסף · `ERR_BLOCKED_BY_RESPONSE` = תוכן מעורב ·
   **`404` = הקובץ באמת חסר בשרת, ורק אז פונים לתמיכת קומקס** עם רשימת ה-URLים.

**לסוכן עצמו זה לא נוגע** — `.chrome-profile/` הוא פרופיל ייעודי בלי תוספים,
ולכן אף משימה לא מושפעת ואין מה לתקן בקוד.

## 💣 "האייקון לא נמצא בשולחן העבודה" — כמעט תמיד שקר (09/09/2026)

כשמשימה נופלת על השגיאה הזאת:

```
"חשבוניות מס ( מכירות )" (a157) לא נמצא בשולחן העבודה —
לא לפי טקסט ולא לפי id. ייתכן שהקיצור הוסר...
```

**אל תריץ `desktop-probe` כתגובה ראשונה, ואל תניח שקומקס סידר מחדש את
השולחן.** עד 09/09/2026 השגיאה הזאת נבעה כמעט תמיד מבאג סדר-פעולות ולא
ממציאות: `openProgram` פתר את הקיצור לפני שהציג את שולחן העבודה, ולכן אייקון
שהיה **מכוסה** בתוכנית פתוחה דּוּוח כאייקון **חסר**.

הבאג תוקן (`resolveShortcut` הועבר לאחרי `showDesktop()`), אבל שני הלקחים
נשארים תקפים:

1. **הזהות של השגיאה מטעה.** "לא נמצא" ב-DOM אינו "לא קיים בקומקס". אם היא
   חוזרת — לצלם את המסך (`npm run snapshot`) ולראות מה באמת מוצג לפני
   שמסיקים שהקיצור נעלם. המסך שמאחורי הכישלון הוא בדרך כלל תוכנית פתוחה או
   פאנל "תוכניות בעבודה", לא שולחן עבודה חסר-אייקון.
2. **ריבוי הרצות זהות הוא סימן לבאג, לא סיבה לנסות שוב.** אותה משימה שנופלת
   פעמיים באותה שורה לא תצליח בפעם השלישית. לעצור, לקרוא את `steps.log` של
   ההרצות, ולהשוות את **המוצלחת** מול **הכושלות** — בממצא הזה ההבדל היחיד
   היה שההרצה שהצליחה פתרה את הקיצור מיד אחרי לוגין, כששולחן העבודה ממילא
   היה למעלה.

### וכישלון כזה כבר לא מצדיק לוגין מחדש

`tools/run.js` נהג לשלם לוגין מלא (40–60 שניות) על **כל** כישלון של משימת
קריאה, מתוך ההנחה שאולי הסשן מת. על שגיאת אייקון זה היה בזבוז כפול: הניסיון
השני מת באותה שורה, כי סשן טרי אינו מציג שולחן עבודה. כישלונות כאלה מסומנים
היום ב-`markSessionUnrelated()` ב-[`src/navigate.js`](../../src/navigate.js)
ונכשלים מיד. אם אתה מוסיף שגיאה חדשה שלוגין ודאי לא יפתור — לסמן אותה גם.

### 🔒 ולוק תקוע נראה כמו הרצה חיה

הרצה שנקטעה משאירה `runs/.lock` עם ה-pid שלה. מערכת ההפעלה ממחזרת pid-ים,
ולכן `tasklist` עשוי להראות תהליך **אחר לגמרי** תחת אותו מספר — ב-09/09/2026

`task` שרשום בלוק, לא רק את קיום ה-pid.

## ⚡ קצב: `mouse.move` על frameset היה הצוואר, לא הקצב האנושי (10/09/2026)

אם מישהו מתלונן ש"הסוכן אִטי" — **הראשון לבדוק הוא לא `minGapMs`**. במדידה חיה
של הקמת חשבונית (הרצה יבשה, 98.5s) הזמן התחלק כך: ~35s תזוזות עכבר, ~27s קצב
מכוון, ו-**~9s בלבד** המתנת שרת אמיתית.

השורש: `Human.click`/`doubleClick` השתמשו ב-`steps: rand(8, 18)`. Max2000 הוא
frameset, ו-Playwright שולח כל mousemove ביניים לכל ה-frames — 61 בעת המדידה —
ולכן **כל step עלה ~שנייה**. נמדד חי: `steps:1` = 737ms, `steps:18` = 18,170ms.

`steps` ירד ל-`rand(1, 2)`, וההרצה ירדה מ-100.9s ל-43.4s בממוצע — **57%** — בלי
לגעת ב-`minGapMs`, ב-`think` או ב-`settle`. קליק בודד: 9.6–18.1s ⇒ 0.6–0.9s.

⚠️ **והעלות מצטברת תוך כדי זרימה** — Max2000 לא מפרק frames, וכל דיאלוג שנפתח
מייקר כל קליק עתידי. בלוג של 08/09 הקליק הראשון עלה 1.2s ובשורה 2 כבר 15.7s.
לכן הרווח במסמך ארוך גדול מהמדידה הזאת, לא קטן ממנה.

⛔ אין להעלות את `steps` בחזרה. האנושיות יושבת ב-`gate` וב-`think`; אינטרפולציה
של העכבר קונה זמן מת בלבד. הפירוט ב-`knowledge/MAP.md`.
