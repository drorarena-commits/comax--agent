# סוכן קומקס

סוכן שמפעיל את פורטל קומקס דרך דפדפן אמיתי על המחשב, בקצב אנושי, בלי API.

## איך זה עובד

Chrome האמיתי שמותקן במחשב (לא Chromium, לא headless) רץ עם **פרופיל ייעודי** בתיקייה
`.chrome-profile/`. מתחברים לקומקס ידנית פעם אחת — הסשן נשמר בפרופיל, והסוכן ממשיך משם.
החלון נראה לעין, אז אפשר לראות כל פעולה שהסוכן עושה.

## פקודות

```bash
npm run open                      # פותח את חלון הסוכן ומשאיר אותו פתוח (מצב לימוד)
npm run logoff                    # התנתקות מסודרת — משחררת את הסשן בשרת
npm run hold -- 45                # מחזיק את המושב 45 דקות של עבודה ידנית (off / status)
npm run snapshot -- <שם-מסך>      # ממפה את המסך שפתוח כרגע -> knowledge/screens/
npm run run -- --list             # מציג את המשימות הקיימות
npm run run -- <משימה> --json '{...}'            # הרצה יבשה (עוצר לפני שמירה)
npm run run -- <משימה> --json '{...}' --confirm  # הרצה אמיתית
npm run run -- stock-matrix        # מטריצת מחסנים -> data/exports/
npm run run -- items-export --json '{"fields":"all"}'  # כל הפריטים לאקסל -> data/exports/
npm run run -- customer-history --json '{"customer":"112447","item":"שנורקל"}'
npm run payroll -- --to <כתובת>    # דוח נוכחות חודשי לשכר -> מייל מקומקס
```

`customer-history` עונה על "מה הלקוח הזה קנה בעבר, ובאיזה מחיר". הוא סורק **בדיוק
שלושה מסמכים** — חשבונית מס (`a157`), חשבונית מס/קבלה (`a132`) והצעת מחיר (`a164`) —
ולא תעודות משלוח או כל דבר אחר. עם `item` הוא מסנן לשורות התואמות וממיין מהישן לחדש,
כך שרואים אם המחיר חזר על עצמו. משימת קריאה בלבד — רצה בלי `--confirm`.


`stock-matrix` מריץ את דוח יתרות המלאי. בכל הרצה הוא קובע את התאריך להיום ואת
המחסנים לפי `reports.stockMatrix.warehouses` בקונפיג, **קורא את השדות בחזרה
מהמסך ומשווה**, ועוצר בלי ללחוץ אישור אם משהו לא תואם. לדריסה חד-פעמית:
`--json '{"warehouses":["1","3"],"date":"31/08/2026"}'`.

## סשן אחד בלבד

לקוד המשתמש בקומקס יש מושב אחד. סגירת החלון **לא** משחררת אותו — השרת ממשיך
להחזיק את הסשן כמה דקות, וההתחברות הבאה נדחית עם "קוד משתמש בשימוש". לכן:

- `npm run open` מתנתק מסודר (`#LOGOFF_Prog`) לפני שהוא סוגר את החלון ב-Ctrl+C.
- `npm run open` מתחבר לחלון שכבר פתוח במקום לפתוח שני ולהתנגש עם עצמו.
- אם החלון נהרג בלי התנתקות — `npm run logoff` משחרר, ואם אין חלון פתוח פשוט
  להמתין כ-3 דקות.
- התחברות שנדחתה עם "קוד משתמש בשימוש" מנסה שוב לבד
  (`login.busyRetries` / `login.busyWaitMs` בקונפיג), במקום להיכשל.

## `npm run ensure` — הפעלה בלי טרמינל פתוח

`npm run open` הוא **מצב לימוד**: הוא מחזיק את החלון ומחכה, וצריך טרמינל שנשאר
פתוח. זה בסדר כשיושבים מול המחשב, וחסר תועלת כשמפעילים את הסוכן מהאייפון.

```
npm run ensure          מוודא שהכל מוכן, ומדפיס READY / NEEDS_LOGIN / FAILED
npm run ensure -- --reset   מנקה חסימת לוגין אחרי תיקון .env
```

מה הוא עושה: בודק את פורט 9222, **משגר כרום מנותק** (detached) אם הוא מת — כלומר
חלון ששורד את סיום התהליך — מחכה שהפורט יעלה, ומוודא שהסשן חי. אם לא, מתחבר
מ-`.env`. `tools/run.js` קורא לו בעצמו לפני כל משימה, אז בדרך כלל לא צריך להריץ
אותו ידנית.

**שחרור המושב — `npm run idle-logoff`.** אין יותר `logoff` בסוף כל משימה: הסשן
נשאר פתוח כדי שבקשות רצופות ירוצו מיד בלי לוגין חוזר. אבל קומקס **לא** ישחרר
לבד — חלון פתוח מתשאל את השרת כל ~90 שניות ומחזיק את הסשן חי, כך שהקוד יישאר
תפוס כל היום וכל עמית יקבל "קוד משתמש בשימוש".

`npm run idle-logoff` מתנתק רק כששני התנאים מתקיימים: אין הרצה פעילה
(`runs/.lock`), ועברו 10 דקות רצופות בלי שימוש (`runs/.last-activity`, נכתב
בתחילת כל הרצה **וגם** בסופה). מיועד למשימה מתוזמנת שרצה כל כמה דקות — יוצא
בשקט כשאין מה לעשות. הסף ניתן לשינוי ב-`COMAX_IDLE_MINUTES`.

**הרצה אחת בכל רגע.** `runs/.lock` נלקח בתחילת כל משימה ומשוחרר בסופה, כולל
`npm run logoff`. הרצה שנייה מסרבת ואומרת מי מחזיק. זה מה שמונע מהרצה מהטלפון
להיכנס על הרצה מקומית — ולהפך.

`npm run open` עדיין שימושי למיפוי ולעבודה ידנית מול החלון; שאר הכלים מתחברים
לאותו חלון דרך פורט 9222.


## הקטלוג — `npm run catalog-csv`

`data/catalog/items.json` הוא טבלת התרגום מקוד/ברקוד למק"ט חלופי, דגם וצבע.
בלעדיו כל דוח מציג ברקודים גולמיים, בניגוד לכלל 5 — והוא **חסר בכל מחשב חדש**,
כי `data/` לא נשמר ב-git.

```
npm run catalog-csv            בונה מהייצוא החדש ב-content/
npm run catalog-csv -- <קובץ>  מקובץ מסוים
```

שניות, בלי לגעת בקומקס ובלי לתפוס את המושב. הייצוא ש-`content/` מחזיק הוא CSV
שכולל `מק"ט חלופי` ו`ברקוד`, ו-`content/` **כן** נשמר ב-git — כלומר הקטלוג
ניתן לשחזור בכל מחשב שמושך את הרפו.

⚠️ זה **לא** אותו מסלול כמו `npm run catalog -- build items`, שמצפה לייצוא
**HTML** של קומקס ולכן מחייב ייצוא טרי של כחצי שעה שתופס את המושב.

## בטיחות

- כל משימה **כותבת** רצה כברירת מחדל ב־dry-run: ממלאת את הטופס, מצלמת, ועוצרת לפני
  כפתור השמירה. רק `--confirm` עובר את הקו הזה.
- משימות **קריאה בלבד** (דוחות) מסומנות `writes: false` ורצות חופשי.
- כל הרצה נשמרת ב־`runs/<timestamp>-<משימה>/` עם `steps.log` וצילומי מסך.

## קצב אנושי

`src/human.js` אוכף רצפה של 2 שניות בין כל שתי פעולות (`pace.minGapMs`), משהה
2–3.5 שניות "מחשבה" לפני פעולות משמעותיות, מקליד תו-תו ב־60–160ms לתו, ומזיז את
העכבר בכמה צעדים עם hover לפני כל קליק. כל הערכים בקובץ הקונפיג.

### למה סגירת חלון לא משחררת

בקשת השחרור היא `Max2000_NET_2022/Server/CloseSession.ashx`, שקומקס שולחת
מתוך `top.onUnload('fset')` — **אסינכרונית, בתוך unload**. הדפדפן הורג בקשות
כאלה כשהחלון נסגר, ולכן היא כמעט אף פעם לא יוצאת. הכפתור התנתקות בסרגל
(`#LOGOFF_Prog`) לא עוזר: כל מה שהוא עושה זה `top.window.close()`, ש-Chrome
חוסם ושלא שולח לשרת כלום.
לכן `logoff()` קורא ל-`onUnload` בעצמו **ומחכה לתשובה**.

### נתונים מקומיים אחרי כתיבה

`data/exports/*.html` הוא צילום מצב ולא נערך לעולם. כל תנועת מלאי שהסוכן מבצע
נרשמת ב-`data/movements.jsonl`, ו-`npm run merge` מחיל את התנועות שנרשמו אחרי
צילום הדוח. כך התמונה המקומית תמיד מעודכנת בלי לזייף את מה שקומקס באמת החזירה.

### דוח מלאי מלא

הדוח של קומקס נעצר ב-1500 שורות, והמגבלה היא על שורות פריטים ולא על מחסנים.
`npm run full-stock` מריץ אותו ב-11 מנות לפי טווחי קוד פריט ומאחד — 12,476
פריטים, כ-25 דקות. `npm run merge-full` מצליב עם הקטלוג ל-`content/`.

## הקטלוג המלא — `items-export`

```bash
npm run run -- items-export                             # ברירת מחדל רזה — 37 עמודות
npm run run -- items-export --json '{"fields":"all"}'   # כל 97 העמודות (58 MB)
npm run run -- items-export --json '{"probe":true}'     # מיפוי הדיאלוג בלבד
```

מסלול אחר מדוח המטריצה: מסך **פריטים** (a84) → לשונית **נוספים** → **יצוא
לאקסל**. אין תקרת 1500 שורות — **כל 13,107 הפריטים בהרצה אחת של פחות משתי
דקות**. ברירת המחדל היא **37 עמודות שנושאות מידע** — ברקוד, קוד חלופי,
מחלקה, קבוצה, ספק, דגם, צבע, מותג, מחיר, עלות. קריאה בלבד, לא נוגע במלאי.

הרשימה הרזה נמדדה: מתוך 101 העמודות של `fields:"all"` היו 45 ריקות בכל
13,107 השורות, שלוש קבועות ושלוש כפילויות מדויקות — 58 MB מול 22 MB.

שלושה דברים שהמשימה אוכפת ואי אפשר לנחש: תיבות בחירת העמודות אינן משפיעות
עד ש-`GetMiunVal()` רץ, תחומי הסינון נשארים דביקים מהרצה קודמת (נמצא מחסן 15
שנשאר מייצוא אחר), והקובץ שיורד הוא HTML ב-windows-1255 בתחפושת `.xls` — 58
MB שלא נפתח באייפון, ולכן הוא מומר ל-CSV ב-UTF-8.
כל מנה נשמרת בנפרד, ואפשר להמשיך אחרי עצירה עם `--from N`.

⛔ **שער המאסטר חוסם.** בקומקס `דגם` ו`צבע` הם ישויות נפרדות מהפריט, ופריט

מהמקור, בלי ריפוד**.

### תעודת העברה → חשבונית

```
node tools/run.js transfer-to-invoice --json '{"transfer":"4700241","customer":"112447"}'
```

קורא תעודת העברה קיימת ומעתיק את שורותיה לחשבונית מס סיטונאית לאותו לקוח.
**מספר התעודה הוא חובה** — לתעודת העברה אין שדה לקוח בכלל (הכותרת שלה היא שני
מחסנים), ולכן אין דרך לחפש "התעודה של לקוח X".

שלושה שלבים, ו-`--confirm` **לא** קולט:

| | מה קורה |
|---|---|
| בלי דגל | קורא את התעודה ומציג את הפריטים. לא נפתחת חשבונית |
| `--confirm` | + פותח חשבונית וממלא כל שורה, ועוצר לפני קליטה |
| `--confirm` + `"file":true` | + לוחץ קליטה |

`file` נפרד מ-`--confirm` בכוונה: קליטת חשבונית מזיזה מלאי ואין לה ביטול.

### מחיר סיטונאי ומע"מ

`wholesale: true` ב-`quote-add-line` מכוון ל**נטו** `round(ברוטו/2)`. דרך ההזנה
נקבעת לפי המחירון של המסמך, שקומקס מצהירה עליו בפוטר
(`לפי מחירון: מכירה ראשי (כולל מע''מ)`):

| | מחירון לפני מע"מ | מחירון כולל מע"מ |
|---|---|---|
| מוזן | מחיר `round(ברוטו/2)`, הנחה 0 | המחיר נשאר, הנחה `(1 − יעד×(1+מע"מ)/ברוטו)×100` |
| שורה | 145.00 | 171.10 |
| **סה"כ** | **171.00** | **171.00** |

האחוז נגזר מהיעד המעוגל — 40.98% ל-289.90 ב-18%, לא 41% עגול. המשימה **עוצרת**
כשהיא לא יודעת אם המחירון כולל מע"מ, וקוראת את הנטו בחזרה מהשדות כדי לוודא
שנחת על היעד לפני שהשורה נשמרת.

**שים לב:** הצעה שלא הופקה נתפסת מחדש — `quote-new` על אותו לקוח יחזור אליה
ויחליף לה את הכותרת. מפיקים (`quote-finalize`) לפני שמתחילים מסמך נוסף.
