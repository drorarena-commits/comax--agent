# סוכן קבלה — `a103`

הצד השני של הכסף. **לא מזיז מלאי — סוגר חשבוניות פתוחות ורושם תשלום שהתקבל.**

**אף מסך של המסמך הזה לא נפתח מעולם.** לא הרשימה, לא הכותרת, לא השורות.
`mapped` הוא כולו `false`, ו-`create` / `addLines` / `finalize` כולם מסרבים.

## למה הוא קיים בכלל אם הוא מסרב

`comax-invoice` (Doc650) מוציא חשבונית ש**לא גובה תשלום**. חשבוניות פתוחות
נערמות בכרטיס הלקוח, ובסט המסמכים אין שום מסמך שסוגר אותן — `Doc652` גובה רק
כשהתשלום יושב על אותו מסמך של המכירה. הקבלה היא החסר הזה.

סוכן שמסרב נכון עדיף על "אין סוכן כזה": הוא אומר בדיוק מה חסר, איך למפות, ומה
החלופה היום. זה בדיוק המסלול ש-`invoice-receipt` עבר לפניו.

## מה ידוע — וזה כמעט הכל

| מה | ערך | מקור |
|---|---|---|
| קיצור | `a103` | `knowledge/desktop-shortcuts.json`, התווית "קבלות" |
| מספר Doc | **לא ידוע** | — |
| נתיב | **לא ידוע** | — |
| רשימה · כותרת · שורות | **לא ידועים** | — |
| אמצעי תשלום | **לא ידועים** | — |
| `printCopies` | **לא ידוע** | — |

**אסור לגזור את מספר ה-Doc או את הנתיב משכן.** `Doc652` כבר הוכיח שהנתיב משקר:
הוא יושב תחת התיקייה של **Doc650** (`Erp/Mehirot/Doc650/InvKab_Mlay/`), ומסכי
התשלום שלו נקראים `Kabala652_*`. אין שום דרך להסיק מזה איפה יושבת קבלה עצמאית.
המספר והנתיב ייקראו מה-URL החי עם `/(Doc\d+)V\.aspx?/i` כשהרשימה תיפתח.

⚠️ **`a146` — "קבלות לעו\"ש" — הוא מסמך אחר.** קבלה להפקדה לחשבון עובר-ושב, לא
קבלה מלקוח. מחוץ להיקף של הסוכן הזה, ואסור למפות אותו במקומו בטעות.

## הממצא שמעצב את הסוכן: **לקבלה אין שורות פריטים**

ארבעת המסמכים הקיימים — `Doc612`, `Doc650`, `Doc470`, `Doc652` — כולם מסתיימים
ב-`<Doc>LinesU` עם `#Prt` (פריט) בתוכו. **לקבלה אין `#Prt`.** השורות שלה הן:

- **אמצעי תשלום** — מזומן · שיק · אשראי · העברה בנקאית
- **הקצאה מול חשבוניות פתוחות** — איזו חשבונית נסגרת, ובאיזה סכום

לכן `engine.addLine`, שמקליד קוד פריט לתוך `#Prt`, הוא הכלי הלא-נכון כאן **גם
אחרי שהמסכים ימופו**. `addLines` מסרב על הבסיס הזה ולא על בסיס המיפוי — כי
המיפוי יושלם יום אחד, והסיבה הזאת תישאר בתוקף.

מי שמעביר `items` לקבלה חושב שזה מסמך מכירה. תשובת "עוד לא ממופה" הייתה מסתירה
את הטעות האמיתית.

הצורה המיועדת, כשיגיע הזמן:

```js
{ payments: [{ method: 'מזומן'|'שיק'|'אשראי'|'העברה', amount, ... }],
  invoices: [{ docNo, amount }] }
```

## `movesStock: false` — וזה לא אומר בטוח

הקבלה לא מזיזה יחידה אחת. היא מזיזה כסף: הקליטה **סוגרת חשבוניות בכרטיס הלקוח**
ורושמת תשלום שהתקבל. **אין "ביטול קליטה"** — יש רק מסמך נגדי, כמו `#Zikuy`
ב-`Doc652`. קבלה שנקלטה על הסכום הלא נכון או מול החשבונית הלא נכונה היא תיקון
בהנהלת חשבונות, לא undo.

לכן `create` ו-`finalize` הם **שני שערים בלתי תלויים**, כמו ב-`invoice-receipt`.
ריכוך של אחד מהם לא מספיק כדי לקלוט מסמך. אל תרכך אף אחד מהשניים.

## המלכודות של השכנים שתקפות גם כאן

1. **`#OK` במסך שורות קולט את המסמך.** במסך כותרת אותו `#OK` רק מתקדם. היציאה
   בלי לקלוט היא `#DoExit` ואז `#Cancel` — אף פעם `#OK`.
2. **`printCopies` — אסור להעתיק משכן.** `Doc650` דוחה 0 ("חובת הדפסה לפחות
   עותק אחד !") ו-`Doc470` דורש 0. ניחוש שגוי עולה מסמך.
3. **`engine.finalize` ידווח "נקלט" על מסמך שלא נקלט** אם דיאלוג הסגירה לא תואם
   ל-`/Close|Kbl|Ishur/i`. מי שיממש קליטה חייב `frames.closeDialog` מפורש, ולוודא
   שהאימות באמת רץ. `Kabala652_*` כבר נפל על זה בדיוק.
4. **`#newRec` יוצר מסמך אמיתי**, גם בהרצת מיפוי.
5. **שם כפתור "שורה חדשה" משתנה בין מסמכים** — `#OKNew` · `#OkNew` · `#OKNext`.
   לקרוא, לא להניח.

## מה כן אפשר היום

**כלום בקומקס.** החלופות:

- **מכירה עם פריטים** → `comax-invoice` (Doc650), ממופה ומאומת חי.
- **תשלום על אותו מסמך של המכירה** → `comax-invoice-receipt` (Doc652). גם הוא
  מסורב, אבל המסכים שלו כבר מופו והוא קרוב יותר לקו הסיום.
- **"מה הלקוח שילם / קנה"** → `comax-history`. קריאה בלבד, עובד.

## איך למפות הלאה

הצעד הראשון הוא **קריאה בלבד** — פתיחת הרשימה. היא לא יוצרת כלום.

```bash
npm run open                          # טרמינל נפרד, מחזיק את המושב
npm run open-program -- a103
npm run snapshot -- receipt-list      # ← מכאן נקראים מספר ה-Doc והנתיב
npm run close -- all && npm run logoff
```

מה שצריך לצאת מהצעד הזה, לפני שנוגעים ב-`#newRec`:

- מספר ה-Doc והנתיב, מה-URL החי
- האם יש `#newRec` ברשימה, ואיזה עוד כפתורים (`#Zikuy`? `#Find`?)
- אילו עמודות יש ברשימה, ואיזה סינון

רק אחרי זה, ובאישור מפורש של דרור:

```bash
node tools/_smoke/click-in-program.mjs "#newRec" receipt-header   # ⚠️ יוצר קבלה אמיתית
```

⚠️ **היציאה בלי לקלוט: `#DoExit` ואז `#Cancel`.**

**אין `receipt-file.mjs`, וזה בכוונה.** כלי שקולט הוא כלי שקולט.

## אחרי שהמיפוי יושלם — מה עוד צריך להשתנות

`registry.chain` מעביר לכל שלב `step.items` וקורא ל-`agent.addLines(ctx, items)`.
**קבלה תצטרך `step.payments`.** השינוי הזה לא נעשה עכשיו בכוונה — קוד שאף אחד לא
יכול להריץ הוא קוד מת, ו-`assertReady` ממילא עוצר שלב קבלה בשרשרת לפני שהמסמך
הראשון מתחיל. זו ההתנהגות הנכונה, לא באג.

השרשרת שמחכה לזה: **חשבונית מס → קבלה**, כפעולה אחת.

`mapped: true` הוא הצהרה שהזרימה רצה מקצה לקצה על מסמך אמיתי — לא ש-snapshot
צולם. הממצאים נכתבים ל-`MAP.md`, לקובץ הזה ול-`.claude/agents/comax-receipt.md`
**באותו commit**.
