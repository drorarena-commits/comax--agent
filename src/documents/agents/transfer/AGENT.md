# סוכן תעודת העברה — `a111`

**לא מופה בכלל.** הסוכן קיים כשלד ומסרב לפעול.

## למה הוא החריג שמצדיק ארכיטקטורת סוכן-למסמך

לתעודת העברה **אין לקוח, אין מחירון ואין מחירים**. הכותרת שלה היא שני מחסנים —
מ- ו-אל — והשורות הן פריט + כמות. כל מה שהמסמכים המכירתיים מתעסקים בו (מחירון,
הנחה, מע"מ, סוכן) פשוט לא קיים כאן. ולעומת זאת הדבר היחיד שכן חשוב לה — שבמחסן
המקור באמת יש את הסחורה — אף אחד מהם לא בודק.

מילוי טפסים גנרי היה מייצר כאן שטויות. סוכן ייעודי מסרב.

`a111` **מעולם לא נפתח** על ידי הסוכן. הוא מופיע ב-`knowledge/screens/*.json`
רק כי כל snapshot לוכד את כל 52 אייקוני שולחן העבודה, ו-`grep "העבר"` על
`knowledge/MAP.md` מחזיר **0 תוצאות**.

ה-id ב-[index.js](index.js) הם שמות של מסמכי מכירה והם כמעט בוודאות שגויים כאן.
הם שם רק כדי שהצורה תהיה גלויה. `mapped: false` מונע מהמנוע לפעול לפיהם.

## איך למפות

```bash
npm run open-program -- a111
npm run snapshot -- transfer-list
# ואז, אחרי לחיצה על הוספה:
npm run snapshot -- transfer-header
```

מה לחפש ולתעד:

1. **הקידומת** — איזה `Doc<מספר>` זה. לגזור מה-URL של ה-frame, לא לנחש.
2. **שני שדות המחסן** — מ- ואל. ייתכן `#StoreM`/`#StoreA`, ייתכן משהו אחר לגמרי.
   הבורר הוא `#CcomboBut<שם השדה>` (מוסכמה שחוזרת בכל המערכת).
3. **האם יש שדה תאריך ופרטים.**
4. **מסך השורות** — אילו שדות מלבד פריט וכמות. האם יש מחיר בכלל.
5. **מה קורה בקליטה** — האם יש דיאלוג אישור, ומה קורה כשאין מספיק מלאי במקור.

בפעולה אחת, עם עצירה בכישלון הראשון.
