# אפליקציית ההזמנות — מחליפה את WeManage Edge

התראת טלגרם ברגע שנכנסת הזמנה באתר ארנה ישראל, עם סיכום מלא בתוך ההודעה,
וממשק מובייל בעברית שמראה את כל ההזמנות לפי סטטוס ומאפשר לשנות סטטוס מהטלפון.

**ומעבר ל-WeManage:** כל הזמנה נבדקת מול קטלוג הפריטים של קומקס. פריט שקיים
באתר ולא בקומקס מפיל את **כל** ההזמנה בסנכרון — היא לא משודרת, המלאי לא יורד,
ואין שגיאה שמישהו רואה. ההתרעה הזאת מגיעה בתוך הודעת ההתראה עצמה.

---

## מה צריך פעם אחת בהתקנה

### 1. מפתחות ה-API של WooCommerce

באתר: **WooCommerce → הגדרות → מתקדם → REST API → הוספת מפתח**

| שדה | מה לבחור |
|---|---|
| תיאור | `אפליקציית הזמנות` |
| משתמש | המשתמש המנהל שלך |
| הרשאות | **קריאה/כתיבה** — נדרש כדי לשנות סטטוס מהטלפון |

המפתח והסוד מוצגים **פעם אחת בלבד**. להעתיק מיד לשתי שורות ב-`.env`.

### 2. בוט טלגרם

1. בטלגרם, לפתוח שיחה עם **@BotFather** ולשלוח `/newbot`.
2. לתת שם (למשל `הזמנות ארנה`) ושם משתמש שמסתיים ב-`bot`.
3. BotFather מחזיר **token** — לשים ב-`.env`.
4. לפתוח את הבוט החדש וללחוץ **Start** (חובה — בלי זה טלגרם אוסר על הבוט לשלוח).
5. להריץ `npm run orders -- chat-id` ולהעתיק את השורה שהוא מדפיס.

### 3. `.env`

```
WOO_URL=https://arenaisrael.co.il
WOO_KEY=ck_xxxxxxxxxxxxxxxxxxxx
WOO_SECRET=cs_xxxxxxxxxxxxxxxxxxxx

TELEGRAM_TOKEN=1234567890:AAxxxxxxxxxxxxxxxxxxxx
TELEGRAM_CHAT_ID=123456789

ORDERS_TOKEN=<מחרוזת ארוכה ואקראית — זו סיסמת הכניסה לממשק>
ORDERS_PUBLIC_URL=https://<כתובת המנהרה>
```

⚠️ `.env` אינו נשמר בגיט — צריך להגדיר אותו בכל מחשב בנפרד, כמו פרטי קומקס.

### 4. גישה מהטלפון — מנהרה

```
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:4180
```

הפקודה מדפיסה כתובת `https://….trycloudflare.com`. את הכתובת הזאת שמים
ב-`ORDERS_PUBLIC_URL`, ובטלפון פותחים אותה **עם** `?k=<ORDERS_TOKEN>` בסוף.
משם הטוקן נשמר בעוגייה ואין צורך להקליד שוב.

באייפון: שיתוף → **הוספה למסך הבית**. מכאן זה נראה ומתנהג כאפליקציה.

⚠️ הכתובת של `trycloudflare` **מתחלפת בכל הפעלה**. לכתובת קבועה צריך מנהרה
בחשבון Cloudflare — שווה את זה ברגע שהאפליקציה בשימוש יומיומי.

## הפעלה

```
npm run orders               # ניטור + ממשק — זה מה שרץ ביום-יום
npm run orders -- check      # בדיקת חיבור: WooCommerce, טלגרם, קטלוג קומקס
npm run orders -- chat-id    # מזהה השיחה בטלגרם, פעם אחת בהתקנה
npm run orders -- test       # שולח לטלגרם את ההזמנה האחרונה, לראות איך זה נראה
npm run orders -- serve      # ממשק בלבד, בלי התראות
npm run orders -- watch      # התראות בלבד, בלי ממשק
```

בדיקות ותצוגה מקדימה, בלי לגעת באתר האמיתי:

```
node orders-app/selftest.js  # 33 בדיקות מקצה לקצה מול WooCommerce מדומה
node orders-app/preview.js   # צילומי מסך של הממשק ל-runs/orders-preview/
```

### ארבע החלטות שכדאי להכיר

**סקירה ולא webhook.** webhook דורש שהאתר יגיע למחשב הזה ברגע ההזמנה. מנהרה
שנופלת לחצי דקה מבליעה הזמנה **לתמיד**. סקירה כל דקה מתאוששת מעצמה — הסבב הבא
מושך את מה שהוחמץ. ההפרש במיידיות הוא עד דקה; ההפרש באמינות הוא בין "הוחמץ"
ל"הגיע באיחור".

**נשמרים מזהי הזמנות, לא רק חותמת זמן.** שעון האתר ושעון המחשב אינם זהים,
ותהליך שנפל באמצע חוזר ושולח שוב. `runs/orders-state.json` מחזיק את המזהים
שדווחו, והחותמת משמשת רק כדי לא למשוך את כל ההיסטוריה בכל סבב.

**הצלבת קומקס בלי נרמול.** לא חיתוך סיומות, לא ריפוד באפסים, לא lowercase —
תוסף הסנכרון משווה מחרוזות, ו"כמעט זהה" הוא בדיוק מה שמפיל את ההזמנה. מק"ט
חסר שהחלק שלפני המקף שלו כן קיים מדווח כ**רמז**, לא כהתאמה.


### כפתור הוואטסאפ — ולמה הוא שואל

בכל הזמנה יש כפתור שפותח שיחת וואטסאפ עם הלקוח, עם טקסט פתיחה מוכן שניתן
לערוך לפני היציאה (שם פרטי + מספר ההזמנה). הכפתור מופיע בשני מקומות: בולט
בתוך בלוק "לקוח" במסך ההזמנה, וכאייקון קטן בכרטיס ברשימה.

**למה יש בחירה בין ביזנס לרגיל:** כשגם וואטסאפ וגם וואטסאפ ביזנס מותקנים
באותו אייפון, **שתיהן רשומות על אותה סכימה** `whatsapp://`, ו-iOS מחליט
לבד מי מהן נפתחת. גם `wa.me` נופל לאותה הכרעה. לכן הדיאלוג שואל תחילה
ומנסה עבור ביזנס סכימה נפרדת, `whatsapp-business://`.

⚠️ **הסכימה של ביזנס אינה מתועדת רשמית על ידי Meta** — היא מה שנצפה בפועל,
לא הבטחה. לכן היא נוסה עם **נפילה חזרה** ל-`wa.me` אחרי 1.2 שניות: אם iOS
לא הכיר אותה, הדף נשאר גלוי ואנחנו פותחים את הקישור הרגיל. הכשל הגרוע
ביותר הוא "נפתחה האפליקציה הלא נכונה", לא "לא נפתח כלום".

✅ **אומת אצל דרור, 14/09/2026 (אייפון):** `whatsapp-business://` **עובד**
ופותח את וואטסאפ ביזנס. הסכימה אינה מתועדת על ידי Meta אבל iOS מכיר אותה.

⚠️ ומה שנלמד באותו אימות: המעבר לוקח **יותר מ-1.2 שניות**, ולכן הטיימר
המקורי ירה את הנפילה חזרה גם כשהמעבר כבר היה בדרך — והמסך קפץ דרך
הקישור הרגיל בדרכו לביזנס. התיקון אינו הארכת הטיימר לבדה אלא **ביטול**
הנפילה ברגע שהדף מאבד מיקוד (`visibilitychange` · `pagehide` · `blur`),
כי משך המעבר תלוי במכשיר ואי אפשר לכייל אותו למספר אחד.

**מה שעדיין לא נבדק:** מכשיר שבו **רק אחת** משתי האפליקציות מחוברת לחשבון
העסקי. שם הבחירה הלא נכונה שולחת ללקוח הודעה ממספר פרטי במקום מהעסק —
וזו בדיוק הסיבה שהדיאלוג שואל ולא מנחש.

**מספר הטלפון מנורמל לפורמט בינלאומי** (`052-555-1234` ← `972525551234`),
ומספר שלא הובן **אינו נשלח לניחוש**: הכפתור פשוט לא מופיע. הודעה שיוצאת
למספר שגוי היא פנייה לאדם זר בשם העסק.

### מגבלות שכדאי לדעת עליהן מראש

- **מחשב כבוי = אין התראות.** זו התוצאה הישירה של הרצה מקומית. הזמנות שנכנסו
  בזמן שהמחשב היה כבוי **כן** ידווחו בהפעלה הבאה, כי חלון הסקירה חוזר אחורה.
- **קטלוג קומקס ישן מייצר התרעות שווא.** הייצוא הלילי ב-03:00 מטפל בזה;
  גיל הקטלוג מוצג בכל התרעה שחורגת מיומיים.
- הרצה ראשונה **אינה** מדווחת למפרע על הזמנות ישנות — אחרת ההתקנה תירה
  עשרות התראות.
